Trajectory Confusion Matrix Generator

Compare noisy (gtrate0) vs ground-truth (gtrate100) trajectories and produce per-action confusion matrices + frame axiom violation analysis.

Quick Start

# Generate spreadsheet for any domain
python generate_trajectory_confusion_spreadsheet.py \
  --base benchmark/data/blocksworld/.../training/trajectories/ \
  --domain-pddl src/domains/blocks/blocks.pddl \
  --output blocks_confusion.xlsx \
  --title "BLOCKSWORLD"

What It Produces

An Excel workbook with one sheet per action + a frame axiom violations sheet:

  • PRE Preconditions checked in prev_state (should be present)
  • ADD Add effects checked in next_state (should be present)
  • DEL Delete effects checked in next_state (should be absent)
  • FA Frame axiom violations: fluents differing from GT whose objects are not a subset of action params

Arguments

--basePath to trajectories dir containing problem0/, problem1/, etc.
--domain-pddlPath to the ground-truth domain PDDL file
--outputOutput .xlsx file path
--titleOptional domain title for sheet headers (default: inferred from PDDL filename)

Programmatic Usage

from pathlib import Path
from generate_trajectory_confusion_spreadsheet import (
    parse_domain_pddl, process_domain
)

action_model = parse_domain_pddl(Path("domain.pddl"))
process_domain(
    base_path=Path("trajectories/"),
    output_path=Path("output.xlsx"),
    action_model=action_model,
    domain_title="My Domain",
)

Key Functions

parse_trajectory()Parse .trajectory file into states + actions
parse_domain_pddl()Auto-extract action models from PDDL (balanced-paren parser)
compute_confusion()TP/FP/FN/TN per lifted fluent per problem
compute_fa_violations()Detect frame axiom violations per transition
process_domain()End-to-end pipeline: parse → compute → write Excel

Implementation Notes

  • PDDL parser uses balanced-paren matching, correctly handles nested (not (pred ?args))
  • Hyphen normalization: action names like pick-up are normalized to pick_up to match trajectory format
  • Trajectory parser strips only the outer closing paren of (:state ...) blocks (avoids the rstrip(')') bug that ate the last fluent)
  • FA detection: a fluent counts as an FA violation only if its objects are NOT a subset of the action's parameters
